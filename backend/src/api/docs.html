POST /api/v1/resolvers

Description: Create a new upstream resolver configuration.

Request Body

Field Type Required Description
ip_address string Required IP address of the upstream DNS server (e.g., "8.8.8.8")
domain string Required Domain pattern to route to this resolver (e.g., "example.com")

Request

curl -X POST http://localhost:8080/api/v1/resolvers \
  -H "Content-Type: application/json" \
  -d '{
    "ip_address": "8.8.8.8",
    "domain": "google.com"
  }'

Response

Success: 201 Created

{
  "success": true,
  "data": {
    "id": 3
  }
}

Error: 500 Internal Server Error

Example (JavaScript)

fetch('/api/v1/resolvers', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    ip_address: '8.8.8.8',
    domain: 'google.com'
  })
})
  .then(res => res.json())
  .then(data => console.log('Created resolver:', data.data.id));

Priority Rules API

Manage DNS priority rules that override resolution based on domain patterns and client filters.

GET /api/v1/rules

Description: List all priority rules.

Request

curl http://localhost:8080/api/v1/rules

Response

Success: 200 OK

{
  "success": true,
  "data": [
    {
      "id": 1,
      "domain": "*.internal.company.com",
      "client_filter": "192.168.1.0/24",
      "target_ip": "10.0.0.5",
      "active": true,
      "created_at": 1718802000,
      "updated_at": 1718802000
    },
    {
      "id": 2,
      "domain": "test.example.com",
      "client_filter": null,
      "target_ip": "127.0.0.1",
      "active": false,
      "created_at": 1718802300,
      "updated_at": 1718803000
    }
  ]
}

Response Fields

Field Type Description
id integer Unique identifier for the rule
domain string Domain pattern to match (supports wildcards like *.example.com)
client_filter string | null CIDR notation for client IP filtering (e.g., "192.168.1.0/24"), null for all clients
target_ip string IP address to return for matching queries
active boolean Whether this rule is currently active
created_at integer Unix timestamp of creation
updated_at integer Unix timestamp of last update

Quick Start Guide

Step 1: Start Goblin DNS Server

# Build and run
cargo run --release

# Or use Docker
docker run -p 53:53/udp -p 8080:8080 goblin-dns

Step 2: Add an Upstream Resolver

curl -X POST http://localhost:8080/api/v1/resolvers \
  -H "Content-Type: application/json" \
  -d '{
    "ip_address": "8.8.8.8",
    "domain": "google.com"
  }'

Step 3: Create a Priority Rule

curl -X POST http://localhost:8080/api/v1/rules \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "*.internal.company.com",
    "client_filter": "192.168.1.0/24",
    "target_ip": "10.0.0.5",
    "active": true
  }'

Step 4: Configure DNS Client

Point your DNS client to the Goblin DNS server:

Linux/macOS:

# Edit /etc/resolv.conf
nameserver 127.0.0.1

Windows:

# PowerShell (Run as Administrator)
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses ("127.0.0.1")

Step 5: Test DNS Resolution

# Use dig to test
dig @localhost app.internal.company.com

# Or nslookup
nslookup app.internal.company.com localhost

Step 6: Monitor Statistics

# Get summary
curl http://localhost:8080/api/v1/stats/summary | jq

# View recent queries
curl http://localhost:8080/api/v1/stats?limit=10 | jq
